[English](README.en.md)｜繁體中文

此工具由虎門科技資深技術工程師 Jeff Hong 洪敬傑提供。

---

## 這個工具解決什麼問題

機構工程師問天線工程師：「**電池放這裡可以嗎？**」

今天的流程是：改模型、跑一次 HFSS、等半分鐘到幾分鐘、回報。所以這個問題
一天只能問幾次，多數擺放決定其實是**憑經驗猜的**。

這個工具讓同一個問題在 **0.2 秒**內得到答案，於是可以改問：
「**這個零件能放的位置有哪些？**」——直接把答案畫成一張圖。

![淨空區地圖](docs/images/gui-10-keepout-map.png)

上圖是一張淨空區地圖：16×16 = 256 個位置，**313 秒**算完，
其中 191 格可放、增益跨度 5.46 dB；同樣的東西用 HFSS 要 **2.1 小時**，
所以實務上沒有人會算。

## 功能

| 功能 | 說明 |
| --- | --- |
| **互動預測** | 3D 視窗拖動金屬件，放開即時重新預測 |
| **與 HFSS 真解並排** | 白色線框是真解，且用**同一個半徑對應**繪製（各自正規化會造成假的相似） |
| **位置敏感度掃描** | 沿單軸掃 21 點約 19 秒，HFSS 要約 14 分鐘 |
| **淨空區地圖** | 2D 網格掃描，畫出「零件能放哪裡」——機構可直接使用 |
| **驗證報告** | 留一種拓樸驗證、逐樣本比對、場型切面、skill score |
| **換天線** | 天線由組態檔描述，換一支是改組態不是改程式 |
| **可行性篩檢** | 15 分鐘判斷「這支天線值不值得建模」，不必先花 2~3 小時 |
| **模型打包** | 打包成 zip，同事拿到就能跑，不必自己重訓 |

## 四道誠實性守衛

模型會**理直氣壯地給出錯答案**，而且四種錯法互相看不見。
每一道都是被實測打臉之後才加的：

| 守衛 | 擋什麼 | 為什麼其他道擋不住 |
| --- | --- | --- |
| ① Skill score | 「通過門檻」但沒學到東西 | 誤差門檻本身會過——實測笨基線 MAE 1.16 dB 就能過 1.5 dB 的門檻 |
| ② 定義域守衛（比對**輸入**） | 輸入超出訓練範圍 | GP 信心值抓不到：沒訓練過的接地面外型，信心值 **0.00（全綠）** |
| ③ GP 信心區間 | 這個場型難不難預測 | 只在輸入合理時有意義 |
| ④ 物理合理性（比對**輸出**） | 輸出的數值不可能 | 見下 |

**④ 為什麼非有不可。** 實測某個組態的峰值真值 1.95 dBi，模型預測 **12.74 dBi**
——小型 PIFA 不可能有那種增益。同一次驗證裡：

| 樣本 | 峰值誤差 | 信心區間寬 |
| --- | --- | --- |
| notch_battery_deep_00 | **10.79 dB** | 0.395 |
| shortgnd_battery_deep_01 | 0.08 dB | 0.396 |

**信心指標到小數第三位幾乎相同**，分辨不出這兩群。定義域守衛也不亮，
因為那個輸入完全在訓練範圍內——**離譜的是輸出**。
場型 MAE 更看不出來（只有 1.20 dB）：少數節點爆掉會被平均稀釋。

> **通則：平均型指標（MAE）會稀釋少數節點的災難性錯誤。
> 一定要同時看極值型指標（峰值、最大誤差）。**

## 目前的驗證結果

| | 內建 PIFA | 客戶案例（合成） |
| --- | --- | --- |
| HFSS 樣本 | 160 | 115 |
| 峰值增益誤差 | 1.16 dB | **0.61 dB** |
| 場型逐點 MAE | 1.40 dB | **0.88 dB** |
| Skill score | 0.566 | 0.261 |
| 推論 vs HFSS | 約 120~200 倍 | 約 120~200 倍 |

留出的都是最極端的 `battery_deep` 拓樸（模型完全沒看過）。
**報告上的數字必須連著「留出的是哪一組」一起看**：同一份資料改成留出
`battery_near`，峰值誤差是 0.26 dB。

### 已知限制（不迴避）

- **峰值增益是不穩定的指標**：同一設定重訓一次，場型 MAE 1.39 → 1.40、
  skill 0.569 → 0.566（幾乎不變），但整體峰值誤差 2.98 → 1.16 dB、
  某個板型的峰值 8.52 → 0.88 dB。峰值是 684 個節點取 max，
  單一節點爆掉就主導結果。**任何基於峰值的結論都需要至少兩次獨立訓練**——
  我們把「某板型不可用」發佈過，後來證實那是單次雜訊
  （見 [ADR-0005](docs/adr/0005-notch-peak-failure-unresolved.md) 的更正）。
- 只訓練 **2.45 GHz 單頻**；一個模型對應一支天線。
- 深零點的絕對值較不準。
- **本版本庫不含訓練好的模型**（約 85 MB，超過 GitHub 單檔上限）。
  到 [Releases](../../releases/latest) 下載，或自己跑一次訓練流程。

## 需要什麼

| 項目 | 用途 | 備註 |
| --- | --- | --- |
| **Ansys SimAI Pro 26.1.0** | 推論引擎 | 必須安裝。工具會用它自己的 `.venv` python 執行推論 worker |
| **Ansys HFSS（AEDT 2026 R1）** | 產生訓練資料 | 只有重建資料集時需要 |
| **Python 3.12（64 位元）** | 後端 | 首次啟動會自動建立虛擬環境 |
| Node.js 20 以上 | **只有開發時需要** | 一般使用不需要，`frontend/dist` 已隨版本庫提供 |

**授權**：`load_model()` 與 `predict()` **不需要授權**，只有訓練（`fit`）需要。
所以互動使用不必開著 SimAI Pro；只有重新訓練時才要。

後端只安裝三個套件（`fastapi`、`uvicorn[standard]`、`pydantic`）。
**torch、stochos、pyvista 不會被安裝**——它們只存在於 SimAI Pro 自己的環境。

## 快速開始（Windows）

雙擊：

```
web_app\start.bat
```

首次啟動會建立 Python 環境（約一分鐘）。網頁幾秒內就會開啟，模型在背景載入，
畫面與主控台都會顯示「模型載入中…已 N 秒」：本機實測約 26～37 秒，**新電腦第一次可能要數分鐘**
（防毒掃描 torch 的上千個檔案），上限 900 秒，可用 `-ModelLoadTimeoutSec` 調整。
瀏覽器會自動開啟；連接埠被佔用時會自動往後找，並在主控台印出實際使用的埠。

- 若偵測到本工具已在執行，會**沿用現有後端**而不是再開一份
- 明確指定 `-Port` 而該埠被佔用時，會直接報錯而不是靜默位移
- 按 `Ctrl+C` 或關閉視窗即結束服務（會確認埠已釋放）

**所有處理都在本機完成**，不會連外，除了首次建立環境時安裝 Python 套件。

詳細操作見 **[docs/操作說明.md](docs/操作說明.md)**。

## 換成自己的天線

天線幾何由組態檔描述，**換一支是改組態不是改程式**：

```bat
set PLATFORM_CONFIG=customer_iot_monopole
```

每個平台的資料、模型、驗證結果完全隔離。範例平台
`platforms/customer_iot_monopole.json`（60×40 mm 板、五段蜿蜒單極）
是**合成的示範案例，不是真實客戶資料**。

完整流程與取樣範圍的注意事項見操作說明第十章。

---

## 開始之前先篩檢（15 分鐘）

完整流程要 2~3 小時才知道結果。先跑：

```bash
python pipeline/screen_platform.py 2 0
```

它量出「可學訊號」——擾動讓場型改變多少，也就是 skill score 的分母。
訊號 < 1.0 dB 代表**這支天線對這些零件不敏感**，那本身就是給客戶的答案，
不必花三小時做一個低分模型再解釋。門檻是從兩個已完成的平台反推的，
不是猜的。詳見操作說明第八章。

## 把模型交給別人

訓練好的模型約 85 MB，**不在版本庫裡**（超過 GitHub 單檔上限）。
兩個平台的模型都放在 **[Releases](../../releases/latest)**：

```bash
gh release download v0.1.0 --pattern "model_platform.zip"
sha256sum -c SHA256SUMS.txt
python pipeline/model_bundle.py unpack model_platform.zip
web_app\start.bat
```

要自己打包（例如重訓之後）：

```bash
python pipeline/model_bundle.py pack
```

還原時會重寫模型路徑（否則它指向打包那台機器的 `APPDATA`，
而 worker 只會說「尚未設定模型」），平台不符則直接拒絕還原。
